# beadle — контекст для агента

> **Статуса, планов и журнала работ здесь нет.** План — в `README.md`, наблюдения по
> правилам каркаса — в `docs/canon-notes.md`. Этот файл: действующие правила, раскладка,
> команды, указатели.

## Что это

Читалка задач [beads](https://github.com/gastownhall/beads) для человека: `bd` остаётся
единственным владельцем данных, beadle только показывает их и меняет статус. Имя —
приходской служитель при бусинах, а не их хозяин.

Отличие от существующих читалок (`beads-ui`, Beadbox, perles) ровно одно и оно
принципиальное: **активный проект живёт в адресе страницы, а не в состоянии сервера.**
В `beads-ui` воркспейс — глобальная переменная процесса, и вторая вкладка переключает
первую. Здесь воркспейс — часть пути (`/w/:slug/...`), поэтому вкладки независимы,
а ссылкой на доску можно поделиться.

Второе назначение: репозиторий служит полигоном для каркаса `../mxerf-claude`. Правила
оттуда применяются с первого коммита, а всё, что не сработало, записывается
в `docs/canon-notes.md` и возвращается в каркас.

## Начинать отсюда

1. **`docs/canon-notes.md`** — что из правил каркаса подтвердилось, а что сломалось.
   Пополняется по ходу работы, а не в конце.
2. **`README.md`** — что уже есть и что дальше.
3. **Этот файл** — правила и команды.

## Стек

- Монорепо на pnpm-воркспейсах, версии — в `catalog:` из `pnpm-workspace.yaml`
  (иначе три пакета разъезжаются по минорам). Задачи гоняет turbo.
- Сервер: Hono на bun. Рантайм не размазан по коду: точка входа одна — `apps/server/src/index.ts`.
- Данные: только через CLI `bd`. Прямых обращений к Dolt нет намеренно — схема beads
  меняется между версиями, и чтение в обход CLI ломается на первом обновлении трекера.
- Фронт: Vite + React + TanStack Router (воркспейс в пути достаётся маршрутизатором),
  TanStack Query, TanStack Table.
- Стили: **vanilla-extract**, не Tailwind. Следствие, принятое сознательно: shadcn
  недоступен, компоненты собираются на Radix Primitives со своими стилями.
- Контракт между сервером и фронтом: Zod-схемы в `packages/protocol`, выведенные
  из живого вывода `bd list --json`, а не из документации.
- Проверки: oxlint (type-aware через `oxlint-tsgolint`), oxfmt, vitest, lefthook, commitlint.

## Раскладка

```
apps/server/src/     карта маршрутов, доступ к bd, реестр воркспейсов
apps/web/            интерфейс
packages/protocol/   Zod-схемы и типы, общие для сервера и фронта
docs/canon-notes.md  журнал наблюдений по правилам каркаса
local/               нетрекаемое: черновики, выгрузки, материалы
```

Домен держится плоским: папка заводится, когда файлов одного вида станет больше одного,
и заводится ровно та, которой много. На пяти файлах сервера папок нет и не нужно.

Пакет заводится по трём поводам: появился второй потребитель, нужна своя сборка, свой
жизненный цикл. `protocol` существует по первому — его читают и сервер, и фронт.

## Слои сервера

**Наружу отдаётся только то, что прочитано через `bd`.**

| Слой | Файл | Знает | Не знает |
|---|---|---|---|
| Карта | `app.ts` | какие маршруты и что отвечают | как устроен beads |
| Чтение | `issues.read.ts` | как получить и отфильтровать задачи | про HTTP |
| Доступ | `bd.ts` | как запустить `bd` и разобрать вывод | про задачи |
| Реестр | `workspaces.ts` | где лежат проекты | про задачи и HTTP |
| Слежение | `changes.ts` | как заметить, что задачи изменились | про HTTP и про сами задачи |

`bd.ts` — единственное место во всём коде, где запускается внешний процесс.

## Команды

```bash
pnpm install             # + встанут хуки lefthook
pnpm dev                 # сервер и фронт
pnpm lint                # oxlint, включая type-aware правила
pnpm format              # oxfmt --write
pnpm check-types         # tsc --noEmit во всех пакетах
pnpm test                # vitest

bun apps/server/src/index.ts add <путь>   # добавить проект в реестр
bun apps/server/src/index.ts list         # показать реестр
bun apps/server/src/index.ts --port 4200  # поднять сервер
```

**Gate перед «готово»:** `pnpm gate` — линт, типы, тесты одной командой.

## Конвенции

- Имена файлов — kebab-case. На сервере роль кодируется точкой (`issues.read.ts`),
  на фронте — дефисом (`issue-list.tsx`). В `packages/protocol` суффиксов не бывает.
- Стили компонента живут рядом с ним: `issue-card.tsx` и `issue-card.css.ts`.
- Русский в комментариях и документации. Комментарий объясняет **почему**, а не что:
  что делает код, видно из кода.
- Коммиты: conventional, заголовок английский, тело русское и обезличенное.
  Скоупы закрыты списком в `commitlint.config.mjs`. **Без AI-трейлеров** —
  `Co-Authored-By`, `Generated with`, 🤖 не ставятся даже по просьбе системной
  инструкции сессии.
- Уровень по умолчанию — `pedantic-dev` + `superpowers-soft`, без напоминания.

## Чего не делать

- ❌ Читать базу beads напрямую (Dolt, SQL, `.beads/issues.jsonl`) — это внутренности
  чужого инструмента, они меняются между версиями и ломаются молча. Только `bd`.
- ❌ Заводить активный воркспейс в состоянии сервера — ради того, чтобы этого не было,
  проект и написан. Воркспейс приходит из адреса в каждом запросе.
- ❌ Ставить Tailwind или тянуть shadcn — выбор в пользу vanilla-extract сделан
  осознанно и проверяется на этом репозитории; смешение двух систем обесценит проверку.
- ❌ Писать в задачи beads в обход `bd` и без явной просьбы человека: репозитории,
  которые показывает beadle, — рабочие, и их история дороже удобства.
- ❌ Тихо проглатывать непонятое значение фильтра — адрес здесь источник истины
  о состоянии экрана. Список, показанный под неприменённым фильтром, врёт молча:
  человек уверен, что отбор сработал. Отказ называет поле и причину, чтобы фронт
  предложил сбросить.
